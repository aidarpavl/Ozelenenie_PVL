# AI-ассистент для озеленения города — MVP (Павлодар)

Веб-приложение на Streamlit для отдела благоустройства и озеленения акимата. Основные функции:
- карта зон со слоями и дорогами;
- подбор растений и смета;
- прогноз приживаемости и план ухода;
- приоритет зон и экологический эффект;
- проблемные зоны, ассистент и отчёты.

> ⚠️ Все расчёты оценочные и рекомендательные. Окончательное решение принимает специалист акимата.
> Данные с пометкой «🧪 синтетика» — демонстрационные. Их нужно заменить данными организатора.

## Запуск

```bash
pip install -r requirements.txt
streamlit run app.py          # откроется http://localhost:8501
```

Через Docker: `docker compose up --build`, затем откройте http://localhost:8501.

При первом запуске модель приживаемости обучается примерно 5 секунд. Дальше она берётся из кэша.

**Streamlit Community Cloud:** главный файл — `app.py`, зависимости — `requirements.txt`. Приложение работает и на Python 3.14: графики строятся через Vega-Lite напрямую, без altair. Если какой-то пакет не соберётся, выберите Python 3.12 в Advanced settings при развёртывании.

### Реальные дороги
Улицы на карте — настоящая геометрия OpenStreetMap. Браузер сам загружает их через Overpass API: если основной сервер не отвечает, пробует два запасных. Данные кэшируются в браузере на 7 дней.
- **Классы:** у каждого класса дорог свои цвет, ширина и обводка. Ширина зависит от зума, мосты рисуются поверх, тоннели — пунктиром.
- **Мелкие улицы:** внутриквартальные проезды и тротуары догружаются при сильном приближении.
- **Подписи:** отдельный слой поверх линий, текст идёт по изгибу улицы.
- **Клик по улице** показывает название, класс, длину и оценку защитной полосы.

Для расчётов (расстояние до дороги, класс, загрязнение, защитные полосы) сервер один раз загружает тот же граф и кэширует его в `data/osm_roads.json`. Если сервер не может достучаться до Overpass, расчёты используют синтетические расстояния и это помечено в интерфейсе. На карте синтетические дороги не рисуются никогда.

### 2ГИС
Задайте ключ в переменной `DGIS_API_KEY` (см. `.env.example`). После этого в списке подложек появится «2ГИС MapGL». Есть также вариант «2ГИС (растровые тайлы)»: перед использованием в продакшене проверьте условия использования 2ГИС.

## Методы и допущения
- **Геометрия.** Данные хранятся в EPSG:4326. Площади и расстояния считаются в UTM 43N (EPSG:32643, формулы Крюгера). Внешние ГИС-библиотеки не нужны.
- **Подбор растений.** Сначала применяются жёсткие ограничения: зимостойкость, засоление, pH, запрет аллергенов и ядовитых видов для школ и больниц, расстояние до зданий, газоустойчивость у дорог. Затем виды ранжируются по штрафам, пригодность 0–100. Схема посадки делится на ярусы. Плотность задаётся по назначению зоны, доля одного вида ограничена (по умолчанию 35%).
- **Приживаемость.** Используется гибрид: 50% экспертные правила (логит-модель) и 50% GradientBoosting (scikit-learn). Модель обучена на **синтетической** выборке, сгенерированной из правил с нелинейностями и шумом. ROC-AUC на тесте 0,766, у одних правил 0,760. Эта метрика показывает, что конвейер воспроизводит заложенные закономерности, но не реальную точность. Для боевого применения нужна калибровка на инвентаризациях акимата: данные подставляются в функцию `train_survival_model`.
- **Объяснимость приживаемости.** Для каждого фактора показан его вклад в п.п. относительно идеальных условий. Диапазон неопределённости строится по расхождению правил и ML.
- **Смета.** Расценки берутся из справочника и сейчас синтетические. Резерв на замену = Σ кол-во × (1 − приживаемость на конец ухода) × (цена + посадка).
- **Эффект.** CO₂ и пыль считаются по видовым коэффициентам взрослого дерева с поправками на рост кроны и выживаемость. Кислород = CO₂ × 0,727. Снижение температуры зависит от покрытия кронами. Источники каждого коэффициента — в «Справочниках».
- **Приоритет.** Взвешенная сумма 6 нормированных факторов, для каждой зоны показан вклад каждого. Дорожная карта под бюджет строится жадным выбором по отношению «приоритет × CO₂ за 20 лет» к стоимости.
- **Ассистент.** Работает локально, без внешнего LLM: распознаёт намерение, вызывает функции модулей и ищет по каталогу. Внешний LLM с tool calling можно подключить вместо функции `_assistant_answer`, инструменты уже выделены.

## Архитектура
Всё находится в одном файле `app.py`, разделы по порядку:
1. Геометрия.
2. Справочники.
3. Данные: синтетика, OSM, импорт и проверка файлов.
4. Аналитика: класс `World` хранит зоны и кэш планов.
5. Ассистент.
6. Отчёты: Excel, PDF, HTML.
7. Интерфейс Streamlit (`main`).

Новые виды, расценки и коэффициенты добавляются через справочники без правки кода. Новые зоны и районы загружаются из файлов.

## Ограничения MVP
- Нет настоящей аутентификации: роль выбирается в боковой панели. HTTPS и вход настраиваются при развёртывании (reverse proxy, SSO).
- Зоны, почвы, насаждения, температура поверхности и население — синтетика, пока нет данных организатора.
- Стрелки направления на односторонних улицах не рисуются: признак одностороннего движения показывается при клике по улице.
